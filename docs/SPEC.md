# 요구사항 명세서 — x4 초해상화 개선 실험 파이프라인

> 기준 문서: `docs/GLOSSARY.md`, ADR-0001 ~ 0006. 용어는 용어집을 따른다.
> 상태: 초안 v3 (2026-11-11, Gemini 교차검증 2차 반영). ADR-0004는 아직 제안 상태라, 11/17 진단 결과에 따라 개선 정의가 바뀔 수 있다.

## Problem Statement

우리는 2인 팀으로 영상처리 기말 프로젝트를 진행한다. 과제는 "강의 개념으로 딥러닝 모델의 약점을 찾아 고치고, 그 효과를 실험으로 입증"하는 것이다. 평가의 85%는 설계 근거·입증·시각 분석·보고이고, 성능 개선폭은 15%뿐이다.

그래서 문제는 "성능을 많이 올리는 것"이 아니다. 아래 조건을 **4주 안에, Colab 무료 T4로, 두 사람이 각자 브랜치에서 AI 에이전트와 함께 작업하면서** 지키는 것이다.

- 베이스라인과 모든 구성이 정말 같은 조건에서 학습되었다.
- 각 개선의 기여를 Ablation으로 분리했다.
- 시드 3개 반복으로 결과의 신뢰도를 보였다.
- 보고서와 발표의 모든 수치를 실제 실행까지 추적할 수 있다.

두 사람과 세 종류의 에이전트가 같은 코드를 고치다 보면 이 조건은 쉽게 깨진다. 예를 들면 이런 일이 생긴다.
- 학습 조건이 슬쩍 달라진다.
- 측정하지 않은 수치가 보고서에 들어간다.
- 색 변환이나 보간 같은 평가 방식이 구성마다 달라진다.

이 중 하나라도 깨지면 결과가 좋아도 "입증"으로 인정받기 어렵다.

## Solution

**실행 파이프라인을 하나만 만든다.** 모든 구성은 이 파이프라인으로만 학습하고 평가한다.

- 공정 비교 조건은 한곳에서 고정한다. 구성마다 다른 것은 개선 스위치(A·B·C, 통제 구성 B′)와 시드뿐이다.
- 실행 하나의 입출력은 정해져 있다. 구성과 시드를 넣으면 아래 결과가 나온다.
  - 실행 기록: 테스트셋 요약 행, 영상별 행, 대표 이미지
  - 체크포인트
- 모든 구성은 RGB SR 결과 하나를 내고, 같은 평가 경로를 거친다. 평가 전에 [0, 1]로 자르고 8비트로 양자화한다.
  - 주 지표: BT.601 Y 채널 기준 PSNR(Y)·SSIM(Y)
  - 보조 지표: PSNR(RGB), 에지 PSNR, LPIPS
  - 함께 측정: 파라미터 수, 고정 입력 크기에서의 추론 시간
  - Bicubic 하한도 같은 경로로 측정한다.
- 결과 표, Ablation 표, 시드별·영상별 Δ, 진단 그림, 사례 영상은 집계 단계가 실행 기록에서 자동으로 만든다. 사람이나 에이전트가 수치를 손으로 쓰지 않는다.
- 같은 체크포인트로 라이브 데모를 한다. VS Code에 연결한 Colab T4에서 Bicubic 하한, 베이스라인, 제안 구성을 3분할로 보여준다.

**작업 흐름**
1. 로컬 VS Code에서 에이전트와 코드를 고치고, 자기 이름 브랜치에 push한다.
2. 얇은 실행 노트북에서 그 브랜치를 Colab T4로 가져와 실행한다.
3. 실행 기록을 다시 자기 브랜치에 커밋한다.

결과 표의 재료가 되는 것은 main에 병합된 실행 기록뿐이다.

## User Stories

### 환경 점검과 데이터 준비
1. As a 팀원, I want 첫날 VS Code Colab 확장에서 T4 연결, Drive 마운트, 원격 런타임의 git push가 실제로 되는지 확인하고 싶다, so that 실행 환경 문제를 본 작업 전에 발견한다.
2. As a 팀원, I want Drive 마운트가 안 되면 데이터는 공유 링크에서 내려받고 체크포인트와 실행 기록은 이름 브랜치에 커밋하는 대체 경로를 쓰고 싶다, so that 환경 문제 때문에 실행 기록의 형식이나 위치가 바뀌지 않는다.
3. As a 팀원, I want 원격 push가 안 되면 실행 기록을 내려받아 로컬에서 커밋하고 싶다, so that 토큰 입력이 막혀도 실행 기록이 남는다.
4. As a 파이프라인 담당 팀원, I want DIV2K 학습셋 HR 영상 800장에 bicubic 열화 모델을 적용해 LR을 만들고 패치 풀을 **한 번만** 생성하고 싶다, so that 두 팀원이 모든 실행에서 같은 학습 데이터를 쓴다.
5. As a 팀원, I want 패치 풀과 테스트셋을 압축 파일 1개로 공유 Drive에 두고, 세션마다 그 파일 하나만 런타임에 복사해 풀고 싶다, so that 작은 파일 수만 개를 하나씩 복사하느라 세션 준비가 길어지지 않는다.
6. As a 팀원, I want 같은 압축 파일을 Kaggle 비공개 Dataset으로도 미리 올려 두고 싶다, so that GPU를 받지 못하면 데이터 준비 없이 바로 Kaggle로 옮긴다.
7. As a 팀원, I want 데이터·출력 경로를 실행 인자로 지정하고 싶다, so that Colab과 Kaggle에서 경로만 바꿔 같은 코드를 돌린다.
8. As a 팀원, I want 테스트셋(Set5, Set14, BSD100, Urban100)의 LR도 학습과 같은 열화 모델과 같은 bicubic 구현으로 만들고 싶다, so that 학습과 평가의 열화 조건이 어긋나지 않는다.
9. As a 팀원, I want 패치 풀에 생성 조건(배율, 열화 모델, bicubic 규칙, 패치 크기, 개수, 생성 시드)과 식별자를 함께 기록하고 싶다, so that 어떤 데이터로 학습했는지 증명할 수 있고, 다른 풀로 학습한 실행이 같은 표에 섞이지 않는다.

### 공통 규칙: 색과 보간
10. As a 팀원, I want 프로젝트 전체가 RGB↔YCbCr 변환 하나(ITU-R BT.601, MATLAB `rgb2ycbcr` 계수)만 쓰길 원한다, so that 학습과 평가의 Y 정의가 어긋나지 않는다.
11. As a 팀원, I want 열화 모델의 축소, Cb·Cr 확대, 전역 잔차의 확대, Bicubic 하한이 모두 bicubic 구현 하나를 쓰길 원한다. 그 구현은 화소 중심 정렬을 쓰고, 축소할 때는 안티에일리어싱을 적용한다. so that 라이브러리마다 커널·좌표·안티에일리어싱이 달라서 생기는 차이가 개선 효과로 오해되지 않는다.
12. As a 팀원, I want 그 bicubic 구현이 MATLAB 호환 참조 구현과 허용 오차 안에서 일치하는지 테스트로 확인하고 싶다, so that SR 관행의 열화 조건과 같다고 주장할 수 있다.

### 구성과 공정 비교 조건
13. As a 팀원, I want 공정 비교 조건을 한 곳에서만 정의하고 싶다, so that 구성마다 조건이 달라질 여지가 없다.
    - 데이터(패치 풀), 에폭 수, 에폭당 패치 수, 학습률, 배치 크기, 패치 크기, 옵티마이저, 학습률 스케줄, 증강, 평가 체크포인트
14. As a 팀원, I want 각 구성을 "베이스라인 + 켜진 개선 스위치 목록"으로만 정의하고 싶다, so that 구성끼리의 차이가 스위치뿐이라는 것이 정의만 봐도 드러난다.
15. As a 팀원, I want 구성이 공정 비교 조건을 덮어쓰려 하면 실행 시작 전에 거부되길 원한다, so that 실수로 조건을 바꾼 실행이 생기지 않는다.
16. As a 팀원, I want 학습 길이를 에폭 수로 고정하고 3시간 상한은 안전장치로만 쓰고 싶다, so that 느린 구성이 덜 학습된 채로 비교되지 않는다.
17. As a 팀원, I want 11/18~19에 가장 무거운 구성으로 파일럿 실행을 돌리고 싶다. 에폭당 시간을 재서, 그 구성이 30분 안팎에 끝나도록 에폭 수를 역산한다. so that 나중에 느린 구성 때문에 에폭을 줄이고 전부 다시 돌리는 일이 없다.
18. As a 팀원, I want 파일럿으로 정한 값을 첫 본 실행 전에 한 번만 고정하고 싶다, so that 본 실행 전체가 같은 값을 쓴다.
19. As a 팀원, I want 모든 실행을 마지막 에폭의 평가 체크포인트로 평가하고 싶다, so that 체크포인트를 고르는 방식이 구성마다 다른 변수가 되지 않는다.
20. As a 팀원, I want 실행이 3시간 상한에 걸려 멈추면 "미완료"로 표시되길 원한다, so that 덜 학습된 실행이 결과 표에 들어가지 않는다.

### 모델, 개선, 통제 구성
21. As a 모델 담당 팀원, I want 베이스라인 ESPCN(RGB 입력, sub-pixel 확대, L1 손실)을 구현하고 싶다. 은닉층은 tanh, 마지막 층은 활성화 없음으로 한다. so that ADR-0002의 비교 기준이 되고, 모든 구성이 같은 구조 규칙을 공유한다.
22. As a 모델 담당 팀원, I want 에지 손실(A)을 켜면 학습 목표가 "L1 + λ × (Sobel 수평·수직 성분 차이의 L1)"이 되길 원한다. 두 항은 모델이 복원하는 채널에서 화소·채널 평균으로 계산한다. so that 에지 흐림을 직접 겨냥하고, 평탄 영역에서도 기울기가 발산하지 않으며, +A와 +A+B에서 손실 크기가 맞는다.
23. As a 팀원, I want λ를 공정 비교 조건처럼 한 번 정하면 모든 +A 계열에 똑같이 적용되길 원한다, so that +A와 +A+B를 비교할 수 있다.
24. As a 모델 담당 팀원, I want Y 채널 처리(B)를 켜면 아래처럼 동작하길 원한다, so that 색 공간 개념에 근거한 개선을 검증하고, 손실 크기가 RGB 구성과 같다.
    - 모델이 BT.601 Y만 복원하고, Cb·Cr은 bicubic으로 확대해 합친 RGB SR 결과를 낸다.
    - 학습할 때 Y는 16~235 범위를 [0, 1]로 다시 정규화해서 쓴다.
25. As a 팀원, I want B를 켰을 때 L1과 에지 손실이 모두 정규화된 Y 채널에서 계산되길 원한다, so that 학습 채널과 손실 채널이 일치한다.
26. As a 모델 담당 팀원, I want 전역 잔차(C)를 켜면 SR 결과가 "bicubic 확대 결과 + 네트워크가 예측한 차이"가 되길 원한다. 구조 규칙은 다른 구성과 같다. so that C 스위치가 바꾸는 것이 bicubic 경로 추가 하나뿐이다.
27. As a 팀원, I want 통제 구성 B′(RGB 입출력, 손실만 정규화된 Y 채널에서 계산)를 시드 3개로 실행하고 싶다, so that B의 효과를 둘로 나눠 보일 수 있다.
    - 목표-지표 정렬 효과: B′ − 베이스라인
    - 입력·용량 변화 효과: B − B′
28. As a 팀원, I want 개선 A·B·C를 서로 독립적으로 켜고 끌 수 있길 원한다, so that 어떤 조합의 구성도 같은 코드로 만들 수 있다.
29. As a 팀원, I want 모든 스위치가 꺼진 구성이 정확히 베이스라인이길 원한다, so that 베이스라인을 따로 관리하는 코드가 생기지 않는다.
30. As a 팀원, I want 손실 계산에는 자르지 않은 출력을 쓰고, 자르기와 양자화는 평가·저장 단계에서만 하길 원한다, so that 학습할 때 기울기가 잘리지 않는다.

### 실행
31. As a 팀원, I want 구성과 시드를 지정하면 학습부터 평가까지 한 번에 끝나는 실행을 원한다, so that 실행 하나가 결과 수치의 최소 출처 단위가 된다.
32. As a 팀원, I want 시드 하나(0, 1, 2)가 두 가지 난수를 모두 정하길 원한다, so that 같은 시드끼리는 구성과 상관없이 같은 데이터를 보고(시드별 Δ로 짝지어 비교), 시드가 다르면 데이터 샘플링 편차까지 반영된다.
    - 모델 초기화 난수
    - 데이터 난수: 에폭마다 패치 풀에서 뽑는 패치와 순서, 증강
33. As a 팀원, I want 같은 구성·시드로 다시 실행하면 결과가 재현되길 원한다, so that 실행 기록을 믿을 수 있다.
34. As a 팀원, I want 각 실행에 실행 ID(코드 커밋, 구성, 시드)가 자동으로 붙길 원한다, so that 어떤 수치든 그 실행까지 거슬러 갈 수 있다.
35. As a 팀원, I want 커밋되지 않은 코드 변경이 있는 상태로 실행하면 경고나 거부가 나오길 원한다, so that 실행 ID의 커밋이 실제로 돈 코드와 일치한다.
36. As a 팀원, I want 체크포인트가 학습 중간과 끝에 저장되고, 같은 실행 ID로 이어서 학습할 수 있길 원한다, so that 무료 런타임이 끊겨도 실행 예산을 아낀다.
37. As a 팀원, I want 실행마다 실제 학습 소요 시간이 기록되길 원한다, so that 승격 조건을 판단하고, 모든 실행이 같은 에폭으로 3시간 안에 끝났음을 보일 수 있다.
38. As a 팀원, I want Colab에서 GPU를 받지 못하면 같은 코드를 Kaggle에서 경로 인자만 바꿔 실행하고 싶다, so that 백업 환경에서 낸 실행도 같은 실행 기록 형식을 따른다.
39. As a 팀원, I want 실행 노트북이 브랜치 가져오기 → 데이터 준비 → 실행 → 실행 기록 커밋만 하길 원한다, so that 로직이 노트북에 흩어지지 않는다.
40. As a 팀원, I want push용 토큰을 실행할 때만 입력받고 어디에도 저장하지 않길 원한다, so that Public 저장소에 토큰이 새지 않는다.

### 평가

## Implementation Decisions

### 모듈 구성
- **색·보간 공용 규칙**
  - 프로젝트 전체에서 RGB↔YCbCr 변환 하나와 bicubic 구현 하나만 쓴다.
    - 색 변환: ITU-R BT.601, MATLAB `rgb2ycbcr` 계수
    - bicubic: 화소 중심 정렬, 축소 시 안티에일리어싱, MATLAB 호환 참조 구현과 일치 확인
  - 이 규칙은 GPU 텐서 연산으로 구현한다.
  - 사용처: 열화 모델, Cb·Cr 확대, 전역 잔차, Bicubic 하한, 평가
  - 라이브러리마다 bicubic 커널·좌표·안티에일리어싱 기본값이 다르다. 그래서 라이브러리 기본 함수를 곳곳에서 직접 부르지 않는다.
- **데이터 준비**
  - DIV2K 학습셋 HR에서 열화 모델(bicubic, 배율 4)로 LR을 만들고, 패치 풀을 한 번 생성한다.
  - 패치 풀과 테스트셋을 압축 파일 1개로 묶어 공유 Drive와 Kaggle 비공개 Dataset에 둔다.
  - DIV2K 검증셋 일부는 학습 곡선 모니터링에만 쓴다.
- **샘플러**
  - 시드에서 파생한 데이터 전용 난수로, 에폭마다 패치 풀에서 정해진 수의 패치와 순서, 증강을 정한다.
  - 같은 시드면 구성과 상관없이 같은 순서가 나온다.
- **구성 해석**
  - 공정 비교 조건과 구성별 스위치를 받아 확정된 실행 조건을 만든다.
  - 구성은 스위치(A·B·C·B′)와 시드 외의 키를 가질 수 없다. 어기면 실행 전에 실패한다.
- **모델**
  - ESPCN 하나를 스위치로 변형한다.
  - 공통 구조 규칙: 은닉층 tanh, 마지막 층 활성화 없음, 같은 초기화 방식
  - B: 입출력을 3채널에서 1채널(정규화된 Y)로 바꾸고, Cb·Cr bicubic 경로를 더한다. 파라미터는 약 37.2K에서 약 24.8K로 줄어든다.
  - C: 출력에 bicubic 확대 결과를 더한다.
  - 바깥 인터페이스는 구성과 상관없이 "RGB LR 영상 → RGB SR 결과(자르기 전)"다.
- **손실**
  - 손실 채널: 기본은 RGB, B가 켜지면 정규화된 Y에서 계산한다.
  - B′는 RGB 출력을 정규화된 Y로 바꿔서 계산한다.
  - 기본 손실은 L1이다.
  - A가 켜지면 같은 채널의 Sobel 수평·수직 성분 차이에 L1을 적용하고 λ를 곱해 더한다. 크기(√)는 쓰지 않는다.
  - 모든 항은 화소·채널 평균이다.
  - 손실에는 자르지 않은 출력을 쓴다.
- **학습(실행)**
  - 확정된 실행 조건과 시드로 에폭 기준 학습을 한다.
  - 체크포인트는 중간과 끝에 저장하고, 같은 실행 ID로 이어서 학습할 수 있다.
  - 평가 체크포인트는 마지막 에폭이다.
  - 3시간 상한에 걸려 멈추면 미완료로 기록한다. 실제 소요 시간과 학습 곡선을 기록한다.
  - 경로는 실행 인자로 받는다.
- **평가**
  - SR 결과 처리 순서: [0, 1] 자르기 → 8비트 양자화 → 가장자리 4화소 자르기
  - 영상마다 PSNR(Y), SSIM(Y), PSNR(RGB), 에지 PSNR(상위 q%), LPIPS(AlexNet, [-1, 1] RGB)를 계산한다.
  - B 계열은 RGB로 되돌리기 전 Y로 잰 PSNR(Y)을 진단값으로 추가한다.
  - 파라미터 수와 고정 입력 크기의 추론 시간(네트워크만 / 전체)을 기록한다.
  - 대표 영상의 Before/After와 확대본을 만든다.
  - Bicubic 하한은 "학습 없는 구성"으로 같은 경로를 지난다.
- **진단**
  - 임의의 SR 결과와 HR로 다음을 만든다.
    - 오차 지도
    - 에지·평탄 영역별 PSNR(Y)
    - 주파수 스펙트럼 비교
    - YCbCr 채널별 오차 분해
    - 최악 영상 목록
  - 1주차에는 정식 파이프라인과 별개로, 최소 기능 스크립트와 같은 함수로 먼저 돌린다.
- **집계**
  - main에 병합된 실행 기록만 읽는다.
  - 계산하는 것:
    - 평균 ± 표준편차
    - Δ, 시드별 Δ와 부호 일관성
    - 평균 Δ와 시드별 Δ 표준편차의 비교
    - 영상별 Δ
  - 만드는 것:
    - 결과 표
    - Ablation 표 (A: RGB·Y 맥락, B: 정렬·입력/용량 분해)
    - 영상별 Δ 분포 그림
    - 사례 영상과 다중 구성 비교 그림
    - 학습 시간 표·학습 곡선
    - 진행 현황 표
  - 보고서와 발표의 모든 수치는 여기서만 나온다.
- **실행 창구(노트북)**
  - 하는 일: 브랜치 가져오기 → 데이터 준비 → 실행 → 실행 기록 커밋·push. 로직은 넣지 않는다.
  - 데이터 준비 기본: Drive 마운트 후 압축 파일 복사·해제. 대체: 공유 링크에서 내려받기.
  - push 대체: 내려받아 로컬에서 커밋한다.
  - 토큰은 실행할 때만 입력받는다.
- **데모**
  - 체크포인트와 대표 영상(또는 업로드 영상)으로 Bicubic 하한 / 베이스라인 / 제안 구성의 3분할과 확대 영역을 표시한다.
  - GPU가 없으면 CPU로 동작한다. 업로드 UI는 선택 기능이다.

### 실행 기록 형식
필드 이름은 코드에서 쓸 영문 식별자로 고정하고, 용어집 용어는 주석으로 붙인다(표기는 설명용).

```
# summary 행: 실행 1회 × 테스트셋 1개
run_id            # 실행 ID = <commit>-<config_id>-s<seed>
commit            # 코드 커밋
config_id         # 구성 (baseline, A, B, AB, C, Bp, AC, BC, ABC, bicubic)
seed              # 시드 ∈ {0,1,2}
patch_pool_id     # 패치 풀 식별자
switches          # 개선 스위치 {A, B, C, Bp}
dataset           # 테스트셋 ∈ {Set5, Set14, BSD100, Urban100}
psnr_y, ssim_y, psnr_rgb, edge_psnr, lpips   # 영상별 값의 평균
psnr_y_pre_rgb    # B 계열 진단값: RGB로 되돌리기 전 Y 기준 (그 외 빈 값)
params            # 파라미터 수
infer_ms_net, infer_ms_total, train_minutes
status            # ∈ {complete, incomplete}

# per_image 행: 실행 1회 × 테스트 영상 1장
run_id, dataset, image_id, psnr_y, ssim_y, psnr_rgb, edge_psnr, lpips
```

- 실행 기록은 실행한 팀원의 이름 브랜치에 커밋한다.
- 체크포인트와 데이터는 Drive(백업: Kaggle Dataset)에 둔다. Drive를 쓸 수 없으면 체크포인트만 실행 기록과 함께 커밋한다.
- 같은 (config_id, seed, patch_pool_id) 조합이 둘 이상이면 집계가 오류를 낸다.

### 실행 목록
- **기본**: Bicubic 하한(학습 없음), 그리고 학습하는 6개 구성 × 시드 3개 = 18회
  - 학습하는 구성: 베이스라인, +A, +B, +A+B, +C, B′
- **승격하면 추가**: +A+C, +B+C, +A+B+C × 시드 3개 = 9회
- **파일럿은 따로 센다**: 진단용 파일럿 베이스라인, 가장 무거운 구성의 에폭 파일럿은 위 목록과 결과 표에 넣지 않는다. 디버깅·파일럿을 합치면 전체 GPU 실행은 30~40회로 본다.

### 추후 확정 값 (파일럿 후, 첫 본 실행 전에 한 번 고정)
- 에폭 수(가장 무거운 구성 기준), 에폭당 패치 수, 패치 풀 크기
- 학습률, 배치 크기, 패치 크기, 학습률 스케줄, 증강
- 에지 손실 λ, 에지 영역 비율 q
- 대표 영상 목록(규칙 적용 결과)

## Testing Decisions

### 좋은 테스트의 기준
- 모듈 내부 구현이 아니라 **바깥에서 보이는 동작**을 검증한다. 예: "구성과 시드를 넣으면 형식에 맞는 실행 기록이 나온다", "같은 영상이면 PSNR이 무한대다".
- GPU 없이 로컬 CPU에서 몇 분 안에 끝나야 한다. 작은 합성 데이터와 1 에폭으로 돈다.
- 에이전트가 PR 전에 스스로 돌릴 수 있어야 한다.

### 테스트 경계 (가장 높은 지점 우선)

1. **주 경계: 실행 인터페이스** (구성 + 시드 → 실행 기록)
   - 모든 구성이 작은 데이터에서 끝까지 실행되고, 형식에 맞는 summary·per_image 행을 만든다.
   - 같은 구성·시드를 두 번 돌리면 지표가 같다.
   - 같은 시드면 구성이 달라도 샘플러가 같은 패치 순서를 낸다.
   - 시드가 다르면 다른 순서를 낸다.
   - 공정 비교 조건을 덮어쓰려는 구성은 실행 전에 거부된다.
   - 구성끼리 확정된 실행 조건을 비교하면 스위치와 시드 외에는 차이가 없다.
   - 스위치별 바깥 동작:
     - **A**: λ=0이면 베이스라인과 손실이 같다. 완전히 평탄한 영상에서도 손실과 기울기가 유한하다.
     - **B**: SR 결과는 RGB 3채널이고, 파라미터 수가 베이스라인보다 적다. 손실 크기가 같은 오차의 RGB 손실과 같은 범위다.
     - **C**: 예측 차이가 0이면 SR 결과는 bicubic 확대 결과와 같다. 음수 차이도 출력에 반영된다.
     - **B′**: 파라미터 수와 입출력이 베이스라인과 같고, 손실만 다르다.

2. **보조 경계: 색·보간 공용 규칙과 평가 모듈** (공정 비교의 심판)
   - Y 변환과 bicubic 축소·확대가 MATLAB 호환 참조 구현(BasicSR)과 허용 오차 안에서 일치한다.
   - 같은 영상이면 PSNR(Y)은 무한대, SSIM(Y)은 1이다.
   - 가장자리 4화소 안쪽의 차이는 지표에 영향을 주지 않는다.
   - 완전히 평탄한 영상에서도 에지 PSNR이 정의된다.
   - 자르기·양자화가 모든 구성에서 같은 순서로 적용된다.

3. **보조 경계: 집계** (고정된 가짜 실행 기록 입력)
   - 평균 ± 표준편차, Δ, 시드별 Δ 부호 일관성이 기대값과 같다.
   - 미완료 표시와 중복 오류가 정확하다.
   - 영상별 Δ와 사례 영상 선정이 정확하다.

### 기존 사례
새 저장소라 기존 테스트가 없다. 지표와 색·보간이 맞는지는 BasicSR의 PSNR/SSIM·`rgb2ycbcr`·MATLAB 호환 `imresize` 구현을 기준으로 삼는다.

## Out of Scope
- 메뉴 3 외의 분야와 x2·x3 배율
- bicubic 외의 실제 열화(노이즈, 블러, JPEG) 학습. 개선 교체로 채택되면 별도 명세로 다룬다.
- GAN·지각 손실 기반 학습, 어텐션 등 스위치 범위를 넘는 구조 변경. 진단 후 교체 대안으로만 검토한다.
- 파라미터 수를 맞춘 B 변형(은닉 채널 확대)
- 하이퍼파라미터 탐색. 값은 파일럿으로 한 번 정하고 고정한다.
- 논문 보고 수치와의 비교(PDF 규칙). 내부 점검용으로만 쓴다.
- 통계적 유의성 검정(t-검정 등)에 근거한 주장
- 배포, 서빙, 웹 서비스화
- Kaggle을 주 실행 환경으로 쓰는 것(백업 전용)
- 실험 추적 SaaS(W&B 등) 연동

**역할**

**ADR-0004는 제안 상태다.** 11/17 진단에서 근거가 약한 개선이 나오면, 이 명세서의 관련 사용자 스토리와 실행 목록도 같이 고친다.

**보고서에 반드시 쓸 해석상 주의점**
- B는 색 공간 변경에 더해 용량 감소(약 33%)와 목표-지표 정렬이 함께 일어난다. 이를 B′로 분해해서 보인다.
- A와 C는 둘 다 고주파 복원을 유도하므로 효과가 겹칠 수 있다.
- 에지 손실이 강하면 전체 PSNR(Y)을 깎을 수 있다.
- B 계열은 RGB로 되돌리는 과정에서 Y 값이 일부 바뀐다.
- C 강의 개념은 "보간 + 주파수 대역 분리"로 설명한다. 열화 모델의 안티에일리어싱은 표본화 정리와 연결한다.
