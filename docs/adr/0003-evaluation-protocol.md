# 평가는 BT.601 Y 채널 기준으로 하고, 자기 베이스라인 대비 Δ만 보고한다

모든 구성(Bicubic 하한·통제 구성 포함)의 출력은 **RGB SR 결과 하나**로 같다. 이 결과를 [0, 1]로 자르고 8비트로 양자화한 뒤, 같은 평가 경로에 넣어 측정한다. 실제로 저장·표시되는 영상을 평가한다는 SR 평가 관행을 따르고, 구성마다 후처리가 달라지지 않게 하기 위해서다.

## 지표

**주 지표: PSNR(Y)·SSIM(Y)**
- 가장자리를 배율(4화소)만큼 먼저 잘라낸다.
- Y 채널은 ITU-R BT.601 정의로 변환한다. MATLAB `rgb2ycbcr`, BasicSR `test_y_channel`과 같은 정의다.
- 영상마다 계산해서 테스트셋 평균을 낸다.

**보조 지표** (가장자리 4화소를 잘라낸 같은 영상에서 계산)
- **PSNR(RGB)**: Y만 보면 가려지는 색 복원 차이를 드러낸다.
- **에지 PSNR**: 에지 영역의 PSNR(Y)을 영상마다 구해서 평균한다. 에지 영역은 각 HR 영상 안에서 Sobel 에지 크기 상위 q%로 정한다. 비율 기준이라 에지가 거의 없는 영상에서도 값이 정의되고, 영상마다 에지 화소 비율이 같다.
- **LPIPS**: AlexNet 백본으로, [-1, 1] 범위의 RGB 입력에서 계산한다.

**PDF 필수 보고 항목**
- 파라미터 수
- 추론 시간: 테스트 영상이 아니라 **고정된 입력 크기**(LR 320×180 → SR 1280×720)에서 잰다. 측정 조건은 T4, 배치 1, FP32, 워밍업 10회 후 100회 반복 평균, GPU 동기화 포함이다. 두 값을 나눠 기록한다.
  - 네트워크만의 시간
  - 색 변환·bicubic 경로를 포함한 전체 시간

  전체 시간에 들어가는 연산은 모든 구성에서 **GPU 텐서 연산**으로 구현한다. 그래야 전·후처리를 CPU로 돌린 구성만 느려 보이는 왜곡이 생기지 않는다.

**테스트셋**: Set5, Set14, BSD100, Urban100

## 결과 표와 해석

- Bicubic 하한 행을 함께 싣는다.
- 각 구성은 시드 3개의 평균 ± 표준편차와 베이스라인 대비 Δ로 보고한다.
- 시드 3개로는 통계적 유의성을 주장할 수 없다(부호 검정으로도 최소 p = 0.25). 그래서 "유의하다"고 단정하지 않는다. 대신 아래 세 가지로 서술한다.
  1. **시드별 Δ**(같은 시드끼리 짝지은 차이)의 부호가 3개 모두 같은가
  2. 평균 Δ가 시드별 Δ의 표준편차보다 큰가
  3. BSD100·Urban100의 **영상별 Δ** 분포
- 논문에 보고된 수치는 내부 점검용으로만 쓰고, 비교 대상으로 싣지 않는다(PDF 규칙).

**영상 선정 규칙** (골라 쓴다는 의심을 피하기 위해)
- Before/After에 쓰는 **대표 영상**은 본 실행 전에 규칙으로 고정한다. 규칙은 테스트셋별로 파일럿 베이스라인의 PSNR(Y)이 중앙값인 영상과 최하위인 영상이다.
- 성공·실패 **사례 영상**은 결과가 나온 뒤 영상별 Δ의 상위·하위에서 자동으로 고른다.

## Consequences

- RGB 베이스라인을 Y 채널로 평가하는 것은 의도된 선택이다. 그래야 Y 채널 처리(B)와 같은 기준에서 비교할 수 있다. B가 갖는 목표-지표 정렬 이점은 통제 구성 B′로 따로 측정한다(ADR-0004).
- B는 Y를 복원한 뒤 RGB로 되돌리는 과정에서 자르기·양자화로 Y 값이 조금 바뀔 수 있다. 그래서 B 계열은 RGB로 되돌리기 전의 Y로 잰 PSNR(Y)도 진단용으로 함께 기록해 그 차이를 보고한다. 결과 표에는 위 공통 경로의 값만 쓴다.
- q, LPIPS 백본, 추론 시간 측정 조건은 처음 정한 뒤 바꾸지 않는다.
