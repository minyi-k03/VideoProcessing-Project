# 공정 비교 조건을 PDF보다 넓게 고정하고, 학습 길이는 에폭으로 맞춘다

PDF는 데이터·에폭·학습률만 같게 하라고 요구한다. 그런데 배치 크기나 증강 같은 다른 조건까지 함께 달라지면, 성능 차이가 개선 때문인지 그 조건 때문인지 분리할 수 없다. 그래서 모든 구성에 아래 공정 비교 조건을 한곳에서 고정한다. 구성마다 달라지는 것은 **개선 스위치와 시드뿐**이다.

- **PDF 요구**: 학습 데이터, 에폭 수, 학습률
  - 학습 데이터는 DIV2K 학습셋 800장에서 한 번 만들어 공유하는 패치 풀이다.
- **팀 추가 통제**: 배치 크기, 패치 크기, 에폭당 뽑는 패치 수, 옵티마이저, 학습률 스케줄, 증강, 평가 체크포인트(항상 마지막 에폭)

**데이터와 시드의 관계.** 패치 풀 자체는 모든 실행이 같다. 다만 에폭마다 풀에서 어떤 패치를 어떤 순서로 뽑을지는 시드로 제어하는 데이터 전용 난수가 정한다.
- 같은 시드끼리는 구성과 상관없이 정확히 같은 패치 순서를 본다. 그래서 시드별로 짝지어 비교할 수 있다.
- 시드가 다르면 다른 패치를 본다. 그래서 시드 간 편차에 데이터 샘플링의 영향까지 반영된다.

풀을 한 번만 만드는 이유는 두 가지다. 매 세션 원본에서 다시 자르는 시간을 아끼고, 두 사람의 학습 데이터를 문자 그대로 같게 만들기 위해서다.

**학습 길이.** PDF 예시 명령의 `--max_hours`처럼 시간으로 자르지 않고 **에폭 수로 맞춘다**. 시간으로 자르면 느린 구성이 덜 학습된 채로 비교되기 때문이다. 3시간 상한은 안전장치로만 둔다.

**에폭 수 정하는 순서.**
1. 11/17 진단으로 개선 A·B·C가 확정되면, 11/18~19에 **가장 무거운 구성**으로 파일럿 실행을 한다. 가장 무거운 구성은 +A+C로 예상하지만, 실측으로 확인한다.
2. 그 구성이 실행 1회 30분 안팎에 끝나도록 에폭 수를 역산한다.
3. 첫 본 실행 전에 한 번만 고정한다.

가장 빠른 구성 기준으로 정하면, 나중에 느린 구성이 시간 목표를 넘을 때 에폭을 줄여야 하고, 그러면 이미 끝낸 실행을 전부 다시 돌려야 한다.

**진단용 베이스라인.** 11/17 진단은 그보다 먼저 임시 설정으로 돌린 파일럿 베이스라인으로 한다. 이 실행은 결과 표에 넣지 않는다. 결과 표의 베이스라인은 공정 비교 조건을 고정한 뒤 다시 학습한다.

**평가 체크포인트.** "검증셋 최고 에폭"이 아니라 마지막 에폭으로 정한다. 선택 절차 자체가 구성마다 다른 변수가 되지 않게 하고, 검증 평가에 드는 시간을 아끼기 위해서다. DIV2K 검증셋 일부는 학습 곡선 모니터링에만 쓴다.

## Consequences

- 개선이 위 고정 조건 중 하나를 바꾸는 종류라면(예: 열화 다양화, 증강), 그 항목만 예외로 개선 스위치로 다룬다. 테스트셋은 어떤 경우에도 바꾸지 않는다.
- 공정 비교 조건을 바꾸면 그전의 모든 실행이 비교 불가능해진다. 바꿔야 한다면 영향받는 실행을 전부 다시 돌린다.
- 모든 실행의 실제 학습 시간을 표로 보고해서, 같은 에폭으로 3시간 안에 끝났음을 보인다.
