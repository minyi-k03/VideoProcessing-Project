# 모든 실행은 VS Code Colab 확장(T4)에서 하고, 결과는 실행자의 이름 브랜치에 커밋한다

AI 에이전트와 같은 편집기에서 개발하기 위해 개발·학습·데모를 모두 VS Code의 Colab 확장에서 한다. 확장에는 T4 런타임을 연결한다. 로직은 모듈에 두고, 노트북은 저장소를 가져와 실행만 하는 얇은 실행 창구로 쓴다. Colab 웹 화면은 평소 실행 환경으로 쓰지 않는다. Kaggle은 PDF에 명시된 대로 GPU를 배정받지 못했을 때만 쓰는 백업이다.

| 대상 | 기본 저장 위치 | 이유 |
|---|---|---|
| 패치 풀·테스트셋 | 공유 Drive에 **압축 파일 1개**로 저장하고, 세션마다 런타임 로컬로 복사해 푼다 | 작은 파일 수만 개를 Drive에서 하나씩 복사하면 매우 느리다. 공개 저장소에는 올리지 않는다. |
| 체크포인트 | Drive | 세션 끊김 대비 |
| 실행 기록·대표 이미지 | 실행한 사람의 이름 브랜치에 커밋 | 커밋이 곧 실행 기록이 되어 수치 출처를 추적할 수 있다. |

## Consequences

- **첫날 점검이 필요하다.** VS Code 확장의 초기 버전에는 Drive 마운트가 인증 창 없이 멈추는 문제가 있었다. 현재 사용자 가이드는 노트북의 Drive 마운트 명령을 기본 기능으로 안내한다. 그래도 첫날 우리 환경에서 아래 두 가지를 확인한다.
  - Drive 마운트
  - 원격 런타임에서 토큰을 입력해 push하기
- **대체 경로를 미리 정해 둔다.**
  - **Drive 마운트가 안 되면**: 데이터 압축 파일은 공유 링크에서 `gdown`으로 내려받는다. 체크포인트는 ESPCN이 약 150KB라서 실행 기록과 함께 이름 브랜치에 커밋한다.
  - **원격 push가 안 되면**: 실행 기록을 Drive나 런타임에서 내려받아, 로컬 VS Code에서 내 Git 자격 증명으로 커밋한다.
  - 어느 경우든 실행 기록의 형식과 위치(이름 브랜치)는 바뀌지 않는다.
- **경로는 실행 인자로 받는다.** 데이터·출력 경로를 코드에 박지 않아야, Colab과 Kaggle에서 경로만 바꿔 같은 코드를 돌릴 수 있다. 데이터 압축 파일은 첫 주에 Kaggle 비공개 Dataset으로도 올려 둔다.
- **토큰은 남기지 않는다.** 저장소가 Public이므로 토큰은 실행할 때만 입력받고, 파일이나 노트북에 남기지 않는다. `.env`와 토큰 파일은 `.gitignore`에 넣는다. Colab Secrets는 VS Code 확장에서 쓸 수 없다.
- **결과 표는 main에 병합된 실행 기록만으로 만든다.**
- **main 보호 규칙.** main은 PR과 승인 1명으로 보호한다. 다만 저장소 관리자는 우회 병합을 할 수 있게 둔다. 동결 직전처럼 상대 팀원이 응답할 수 없을 때만 쓰고, PR에 이유를 남긴다.
